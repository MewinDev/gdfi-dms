# Glossary

The key words for the workflow. Use exactly these in screens, emails and reports.

Last updated: 12 November 2026 (PHT)

| Word | Meaning | Who | Effect on the clock |
|---|---|---|---|
| **Journey** | The loan's record, read three ways: **Story** (what happened, newest first, one sentence per real event, grouped under a date row), **By document** (each transaction from Opened to Done, with what held it up) and **Full log** (every step, including automatic ones, for checking). "Where it is now" sits above all three. Reading it changes nothing. See [How to read the Journey](03-loan-associate.md#how-to-read-the-journey). | Everyone who can open the loan file | None (the clock never pauses) |
| **Missing paper** | A paper the LA marks Missing on its row (Check papers), with a reason (Settings, Missing paper reasons) and remarks (5 to 500 characters) for that paper. It does not block the file: Send waits only until every missing paper has its remarks. Ends when it is marked Received, with the date it arrived. A paper the processor asks for in a Return to LA is a missing-paper request instead (closes when the paper is ticked). | LA (papers:mark_missing); Received: papers:receive_late | None |
| **Include in this file** | The tick on an optional paper. Off: the paper is ignored (nothing expects it, it needs no remarks, the DP cannot return the file for it). On: it behaves exactly like a required paper. | LA | None |
| **Complete with exceptions** | A file through the vault gate while a paper is still Missing (with remarks). It stays flagged until every missing paper is Received. | System | None |
| **On hold** | The work waits on someone outside our hands (borrower, LTO appointment). A reason category and remarks (at least 5 characters) are both required; the system records who and when (PHT); there is no expected resume date. Everyone who can see the loan file sees the same summary: "On hold: {reason}", the remarks as typed, "Put on hold by {name} · {date and time} · {n} ago" and "To continue: press Resume and write what changed". It shows in the On hold banner at the top of the To do tab, at the top of Check documents and the DP job, as one line under the transaction's name in the lists ("On hold: {reason} · {n days}"), in the Open items card (reason and the first line of the remarks) and as two Journey entries (put on hold, resumed). Resume asks for remarks too. Older holds without remarks show "No details were written."; only the person who put it on hold can add them. The reason comes from the managed list (Settings, Hold reasons) and the hold keeps a copy of its name. Remarks for Put on hold, Resume and Add details: 5 to 500 characters. | LA or DP (resume: only the hold owner) | The clock keeps counting ("The TAT clock keeps running"); hold time is shown beside it |
| **Hold owner** | The person who can resume a hold. It starts as the person who put the transaction on hold and changes only by a Transfer hold. Only the hold owner can resume it or add its details; everyone else, Admin and supervisors included, sees Resume disabled with "Only {name} can resume this." (or "Needs to be resumed by {name}. Ask your supervisor if {name} is away."). | LA or DP | None |
| **Locked** | A transaction on hold: readable, but nobody can change it (papers, missing paper, funds, notes, send, pull back, update, change processor, the DP's accept, stages, check and verify, complete, forward, decline, return) until the hold owner resumes it. The refusal says "Locked: on hold by {name} since {date and time}. Only {owner} can resume." Per transaction: the other transactions of the loan keep working. Finance: request, approve, release, top-up and carry-over are refused ("Locked: on hold by {name} since {date and time}."); receipts, cash returns, liquidation, close and exceptions stay allowed. | System | The clock keeps counting |
| **Transfer hold** | A person whose role has "Move a hold to another person" (`holds:transfer`: the Branch Supervisor and Admin by default; not Finance) gives a hold to another active person with the same work role who also has access to the loan's branch (an LA for an LA hold; a DP for a DP hold), with remarks (5 to 500 characters). Only holds in the branches of their own access (Admin: All branches). The new owner becomes the only person who can resume it; the reason, remarks, start and "put on hold by" stay; it stays locked. They never resume it themselves. Recorded as "Hold transferred from {A} to {B} by {C} · remarks · date and time". | Branch Supervisor or Admin | None |
| **Branch Supervisor** | The built-in role for a branch or area supervisor (an area supervisor is the same role with Area access on the person). Sees the loans of their branches, moves holds to another person there, resolves any problem there, sees the Monitoring pages and the TAT report. No money, Settings, users, roles or branch imports. | Branch or area supervisor | None |
| **Papers handed over** | On a Return to LA the DP ticks every paper received at Accept as handed over to the LA. The LA confirms them in the "Do this now" card ("Confirm the papers you received"): "All 7 received" in one click, or "Check each paper" to mark a paper Not received, which raises a Problem naming it. Send again stays blocked until the papers are confirmed (or none were received). | DP, then LA | None |
| **Cash advance** | Cash Finance hands to the processor for a job (funds type CA). Finance enters a voucher or reference at release. Liquidated with receipts, as before. | DP asks, Finance approves and releases | None |
| **Fund transfer** | Money Finance sends to the processor's account instead of cash (funds type FT). Same steps as a cash advance; at release Finance enters the transfer reference number, the transfer date and the receiving account (bank or e-wallet, account name, last 4 digits only). The button says "Send transfer" instead of "Release cash". | DP asks, Finance approves and sends | None |
| **Expense kind** | What a cash advance or fund transfer line is for (Settings, Expense kinds; see `funds:kinds_view` and `funds:kinds_manage`). Notary fee, PPSR fee, LTO fee, Transport and kinds added later, then Other, always last. Names are 2 to 40 characters, unique ignoring capitals and spaces. A kind is never deleted: it is made inactive (not offered for new requests or rules; old records keep it). A kind's amount is Person enters it, Suggested or Fixed; a Cash-advance rule's Suggested amount comes first and the rule's maximum always applies. | Finance, approvers, Admin | None |
| **Other** | The built-in expense kind for anything that fits no other kind. It cannot be renamed, made inactive or given an amount. The person must say what it is ("What is this expense?", 3 to 60 characters), shown as "Other: Courier"; old lines without text show "Other (not described)". In a Cash-advance rule, Other covers any kind without its own rule. Descriptions typed 3 or more times in 90 days appear in "Often typed as Other" so they can become a kind. | DP, Finance, approvers | None |
| **Who handles it** | For each funds type, the people who can approve, release and settle it, read from the ticks on their roles (Settings, Funds types). Cash advances and fund transfers are handled by different people; each step is one tick per type ("Release fund transfers"). When nobody can do a step, a soft amber line says so ("Nobody can release fund transfers.") and the Admin is told about waiting requests. | Admin reads it; Finance and approvers do it | None |
| **Request number** | A funds request's number: `CA-<year>-<4 digits>` for a Cash advance, `FT-<year>-<4 digits>` for a Fund transfer, each with its own running number per year. When the type changes before release, the request gets the next number of the new type and keeps the old one as "Formerly CA-2026-0008"; the search finds both. | System | None |
| **Funds type** | Which kind of funds a request is: Cash advance or Fund transfer (Settings, Funds types; `fundtypes:manage`). Shown as a small pill with its code and name ("CA · Cash advance", "FT · Fund transfer"). The DP picks it on the request (default Cash advance); Finance can change it before release, with remarks. A record keeps the type's id and a copy of its name, so a rename never changes old records. | DP, Finance | None |
| **Cash to settle** | Cash released for a job that went back to the LA (declined or returned). The job is no longer the DP's, but the advance stays in the DP's My funds and in Finance's Outstanding list, marked "Cash to settle", until it is liquidated and closed. New cash for a re-send is requested again like any new job. | DP, Finance | None |
| **Round** | One send to a Document Processor. When the DP declines or returns it, the LA who sent it fixes it and sends it again: round 2, and so on. The processor is chosen again (nothing pre-selected). A "Round 2" chip shows on the transaction for the LA and Admin; the Journey lists every round. | LA, DP | The clock never restarts |
| **Problem** | A fault (system down, wrong paper, closed office). Red, own timer. Admin may tag "Outside our control". | LA or DP | The clock keeps counting |
| **Pull back** | The LA cancels a send before the DP accepts. | LA | Clock continues from when it first became ready |
| **Return to LA: papers needed** | After accepting, the DP sends the job back with findings: what is wrong or missing (the papers, where possible) and remarks (5 to 500 characters). The DP hands over every paper received at Accept; there is no "keep the papers" or "keep the cash". It goes back to the specific LA who sent it (every active LA of the branch if that LA is inactive), who confirms the papers, fixes it and sends it again (a new round). The DP does not see the job again. | DP | Clock continues; not a Problem |
| **Pasuyo** | A second processor takes over or helps. The cash is decided first (return it, or hand the balance over). | LA at Send, DP on a job | Clock continues |
| **Decline** | The DP says no before accepting, with one reason (No capacity, Wrong job for me, Papers not complete, Other) and remarks (5 to 500 characters). It goes back to the specific LA who sent it ("Declined by the DP"), who fixes it and sends it again (a new round). The DP does not see the job again. Decline is before accepting; Return to LA is after. | DP | Clock continues |
| **Check and verify** | The DP's last stage: every paper ticked as received back and complete before Complete job and Forward. A paper not back becomes a Problem (Missing paper). | DP | The clock keeps counting |
| **Forward to branch** | The DP sends the finished package: chooses the branch, then the named LA, and confirms the paper count. Never automatic. | DP | Clock continues |
| **Package incomplete** | The receiving LA recorded the package Incomplete (or a blocking Other). It goes back to the DP to correct and forward again. | Receiving LA, then DP | Clock continues from acceptance; never paused |
| **Returned to DP** | The custody record of one paper ticked in Check and verify as received back and complete. | DP | None |
| **Capacity** | How many open jobs a processor takes (open = assigned + in process + on hold). Default 10 (Settings, Processor capacity); a processor can have their own number. | Admin (`dpcapacity:manage`) | None |
| **Availability** | Free places over capacity, rounded, with the numbers: "60% · 4 of 10 in use". Available from 40%, Busy from 1% to 39%, Full at 0%, On leave (counts as 0%; shown disabled in the Send panel). Shown on the Monitoring page and beside each processor in the Send panel. | System | None |
| **Overdue** | An open job whose current step is past its due date (the same late rule as the TAT chips). Counted on the Monitoring page as of now. | System | The clock keeps counting |
| **LTO advisory** | A warning about an LTO office (System down, Office closed, Long queue, Other) with remarks, filed by a DP from a job at an LTO stage or by Operations. Active until resolved with remarks; shown on the office choice, the DP job and the Monitoring page. Never blocks anything and is not in the Journey. | DP, Operations Monitor | None |
| **MyLoans change** | MyLoans data differs from the saved copy. Minor changes (area, division, company) update silently; borrower details (name, address, contact number, CIF, CIN) are a "MyLoans correction" reviewed by the branch supervisor or approver; the rest need Admin review. A loan moved to another branch in MyLoans is a material change: Admin sees the old and new branch and who gains or loses sight of it, and the loan's branch changes only when Admin applies it. | System, Admin | None |
| **PN** | The promissory note number, the loan's key: GD + branch code (3 digits) + year (4 digits) + 9 (the MyLoans system) + running number (5 digits), for example GD1012026900001 (15 characters). The rules are an Admin setting (Settings, System, PN format; the check can be switched off). Spaces, dashes and dots are removed first, so a pasted "gd 101-2026-9-00001" works. A wrong PN shows "This does not look like a PN. Example: GD1012026900001" and the part that is wrong ("The year is in the future"), and never reaches MyLoans. Always shown as stored, in monospace. | Everyone | None |
| **Branch code** | The 3-digit MyLoans code of a branch (100 to 999, unique; Antipolo is 101). A branch without one shows "Code needed" (codes are never guessed). Loans, users and everything else point at a branch by its internal id, so a rename or a code fix breaks nothing. | Admin | None |
| **Division** | A MyLoans business line: Branch Division, Car Financing Division, Truck Financing Division, REM Division, Brand New Car Division, REF Division. Not a region. | Admin | None |
| **Area** | A MyLoans region inside a Division ("LUZON 1 (NGMA + RIZAL)", "Luzon 3 - CFD"). The same area can appear under two divisions, so a branch keeps both, and the access tree and Monitoring use the pair (Division, Area). | Admin | None |
| **Branch review** | Differences between the MyLoans branch list and the DMS: New branch, Renamed, Code changed, Area or division changed, Closed (inactive), Reopened, Not in the last list, Unknown branch code seen in a PN (and new or renamed areas and divisions). Each has Accept (applies it, after showing who gains or loses access) or Ignore. Nothing changes silently and nothing is deleted. | Admin (`branches:review`) | None |
| **Opened at / Current branch** | The PN's branch code says where the loan was opened (a hint only, it never changes). The loan's current branch always comes from the MyLoans branch field. The Loan File shows "Opened at Antipolo", or "Opened at Antipolo, now at Angono" when they differ (branch names only; a PN code that is not a branch yet still says its code). Everyday screens (Loan File, search, Loans, Monitoring, the TAT report, Users) show branch names only; branch codes stay in Settings > Branches, Import from MyLoans, the Branch review and the PN format setting. | Everyone | None |
| **Branch access** | Where a person works (roles say what they can do). All branches, or Selected: whole Divisions, whole Areas and single Branches together, minus exceptions (a branch unticked inside a ticked Area). A ticked Area includes a branch added to it later. Each person who works on loans has a home branch inside their access, the default for new work and sending. Admin people have All branches (stored on each person). Changing it needs `access:manage`. | Admin (`users:edit`) | None |
| **Hide from DMS** | A switch on a test or retired branch (`branches:manage` or `branches:review`): it leaves pickers, trees, filters and counts and cannot be chosen for new work, but stays on old loans. It survives every import. The import only suggests it ("Looks like a test or unused branch"); Admin decides. | Admin | None |

Never use the word "Pending" for these states.
